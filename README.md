# 교실 온도 처방전 v1.1 — 배포·테스트 안내

## v1.1에서 바뀐 것 (사용자 테스트 피드백: "잡다한 정보가 많아 진짜 정보가 뭔지 알기 어렵다")

- 처방 한 줄(예: `난방 20°C`)을 가장 크게, 이유는 쉬운 말 한 줄로
- 판단 근거는 숫자 세 개(지금 실내 · 30분 뒤 AI 예상 · 바깥)만
- AI 채점 기록·그래프·입력·기록 재생은 '자세히 · 설정'으로 접음
- 같은 장면(노트북 1280×720 첫 화면)에서 보이는 숫자 26개 → 15개, 글자 351자 → 231자
- '자세히 · 설정'에 화면 열림 시간과 바깥 기온 표시 시간이 나옴(T3·T4를 F12 없이 확인)
- 고친 버그: 기록 재생 뒤 직접 입력하면 재생 기록의 예측이 처방에 섞이던 것
- 사용자 테스트 페이지: '시작'을 눌러야 시간을 잼(첫 참가자 시간이 길게 잡히던 문제)

micro:bit(DS 센서 세트) 실내 온도 + 기상청 바깥 기온 + **HAIP의 30분 뒤 온도 예측 AI**로
냉난방기 설정을 처방하는 웹 서비스. 화면·처방·AI는 모두 교실 노트북 브라우저 안에서 돌고,
기상청 키만 Vercel 서버 함수에 숨긴다.

| 기능 | 내용 | 파일 |
|---|---|---|
| F-01 | micro:bit 기록 받기(Web Serial)·직접 입력·저장 | `js/serial.js`, `js/samples.js` |
| F-02 | 바깥 기온(기상청 초단기실황, 키는 서버에만) | `api/weather.js` |
| F-03 | 처방 카드(학교 기준 난방 20°C·냉방 26~28°C, 창문 열림이면 잠시 끄기) | `js/rules.js` |
| F-04 [AI] | 30분 뒤 예상 온도 → 처방에 반영 | `js/model.js`, `model/forecast_model.json` |
| F-05 | 체감 투표 + 지난 예측 자동 채점 | `js/app.js` |
| F-06 | 오늘 온도 그래프 | `js/app.js` |
| F-07 | 급하강 알림(10분에 1°C 넘게 떨어지면 '창문 확인') | `js/app.js` |

AI 모델: HAIP `temp_forecast_30min.keras`를 그대로 옮김(가중치 376개).
입력 = 최근 30분(5분 × 6) 온도·습도·움직임 + 기압 변화 → 출력 = 30분 뒤 온도 변화(°C).

## 1. GitHub에 올리기 (5분)

1. github.com → **New repository** → 이름 `classroom-temp-rx` → Create.
2. **uploading an existing file** → 이 폴더 안의 파일·폴더를 전부 끌어다 놓기 → **Commit**.

## 2. Supabase — 기록 저장 (5분)

1. supabase.com → **New project**.
2. **SQL Editor** → `supabase.sql` 내용을 붙여 넣고 **Run** (표 3개 + 추가·읽기만 허용).
3. **Project Settings → API**에서 Project URL과 `anon` `public` 키를 복사해 `config.js`에 넣고, GitHub에 다시 올린다.
   (anon 키는 공개용 키라 브라우저에 있어도 됨. 비워 두면 저장 없이 화면만 동작)

## 3. 기상청 서비스 키

- 공공데이터포털 **기상청_단기예보((구)_동네예보) 조회서비스** 활용 신청 → 마이페이지 → **일반 인증키(Decoding)** 복사.
- 학교 위치 격자(nx, ny): 같은 페이지 활용가이드에 있는 격자 엑셀에서 학교 동네를 찾는다.

## 4. Vercel 배포 (5분)

1. vercel.com → GitHub로 로그인 → **Add New → Project** → `classroom-temp-rx` **Import**.
2. Framework Preset은 **Other** 그대로. **Environment Variables**에 세 개:
   - `KMA_SERVICE_KEY` = Decoding 키
   - `KMA_NX` = 학교 nx, `KMA_NY` = 학교 ny
3. **Deploy**. 생긴 주소는 포스터에 쓰지 않는다(과제 규칙).
4. 이후 GitHub에 고친 파일을 올리면 자동으로 다시 배포된다.

## 5. 배포 뒤 테스트 → 포스터 ⑥ 테스트 표

| 번호 | 확인 | 방법 | 통과 기준 |
|---|---|---|---|
| T1 | 처방 정답표 20개 (F-03) | 이미 통과 — `node --test tests/*.test.mjs` | 20/20 |
| T2 | 기록 재생 287개 (F-04) | `주소/?demo=1&at=297&pause=1` → AI 칸 맨 아래 | "지난 예측 287개 · AI 0.41 · 그대로 0.61" |
| T3 | 바깥 기온 (F-02, N-2) | 교실 노트북에서 열기 → 바깥 기온 칩. F12 → Network → `weather` 응답에 키가 없는지 | 5초 안 표시, 키 없음 |
| T4 | 화면 열림 (N-1) | F12 → Network → 새로고침 → 아래 **Load** 시간 | 2초 이하 |
| T5 | micro:bit 표시 (F-01) | micro:bit 연결 → 다음 기록 때 실내 온도 | 첫 기록(5분 안)에 표시 |
| S2 | 우리 교실 AI 오차 [AI] | 센서를 하루 켜 두기 → AI 칸 "지난 예측 n개 채점" 사진 | AI 오차 < 그대로, n ≥ 30 |

## 6. 교실에서 하루 쓰기 (S2)

1. DS micro:bit 프로그램에 한 줄 추가 → `microbit/README.md`.
2. 교실 노트북 크롬에서 주소 열기 → **micro:bit 연결**.
3. 30분 뒤부터 AI 예측. 하루 켜 두면 AI 칸 맨 아래 **지난 예측 n개 채점 · AI 오차 · 그대로 두기**가 쌓인다 → 집에 가기 전에 사진.
4. 담당 학생은 조작기를 바꿀 때마다 **처방대로 맞췄어요**를 누른다(설정 변경 횟수가 남음).
5. 노트북 절전(잠자기)을 끈다. 잠들면 연결이 끊긴다.

## 7. 사용자 테스트 (S1·S3, 5명 이상)

1. 교실 노트북에서 `주소/usertest.html`을 연다. 너는 관찰자, 참가자는 왼쪽 화면만 본다.
2. 참가자는 **분대원이 아닌 사람 5명 이상**. 이름은 쓰지 않고 역할만 고른다.
3. 과제 3개를 읽어 주고 답하는 순간 버튼을 누른다 → 마지막 점수·의견 → **저장 → 다음 사람**.
4. 끝나면 **CSV 내려받기** → 보내 주면 포스터에 넣는다.

| 성공 기준 | 무엇으로 | 기준 |
|---|---|---|
| S1 | T1 "조작기를 어떻게 맞추나요?"를 10초 안에 맞게 | 80% 이상 |
| S2 [AI] | 교실 하루 기록의 지난 예측 채점 | AI 오차 < 그대로 두기 |
| S3 | "이 처방대로 맞추겠다" 1~5점 | 평균 4점 이상 |
